# 任务：改进个人财报跟踪面板

## 角色
你是实现型 agent，帮助一位个人投资者改进其现有的“财报跟踪面板”。

## 背景
- 用户是个人投资者（同时是券商后台开发，有技术能力），持仓以松发股份（恒力重工借壳）为主。
- 已有工具：三季报跟踪 MVP（每天添加符合条件的股票）；复盘面板 ReviewGrowth（https://panhaoneo.github.io/ReviewGrowth）；多个静态看板站点（panhaoneo.github.io 下）。
- 使用现实：每天可投入维护时间 ≤5 分钟；工具必须轻量。

## 第 0 步（必须先做）
1. 向用户询问并找到现有跟踪面板的仓库路径，阅读其实现，弄清现有数据结构与页面。
2. 阅读以下参考文件（同机可访问时）：
   - `content/assistant/07_knowledge/公司跟踪卡/松发-跟踪卡-v1.md` —— 跟踪卡样例（目标形态）。
   - `content/assistant/07_knowledge/参考资料/中远海能航线全景-跟踪方式解剖.md` —— 逐单元跟踪方法（六要素）。
   - `content/assistant/07_knowledge/参考资料/利伏于众声未至-方法卡.md` —— 方法论（逻辑穿透五问、证伪条件、两阶段）。
   - `content/assistant/07_knowledge/交易纪律.md` —— 止损规则。
3. 输出改进方案（数据结构 + 页面结构 + 每日使用流程），经用户确认后再实现。

## 改进目标
把面板从“数据登记表”升级为**一手证据链跟踪系统**。核心要求：

1. **标的跟踪卡**（每只股票一张），必须包含：
   - 加入理由（一句话）、加入日期、筛选门槛记录（增速 / 量价齐升 / 股价新高 / 机构认可，四项可勾选）。
   - 逻辑穿透五问：需求增长 / 供给受限 / 定价权 / 利润传导 / 现金转化——各一段，可更新，带时间戳。
   - 证伪条件清单：每条可勾“已触发”；触发时在总览页高亮。
   - 状态三态：逻辑强化中 / 待验证 / 已证伪。
2. **事件流**：每只标的有时间线，记录事件（签约 / 交付 / 公告 / 指标更新 / 判断变更）。事件是每天唯一需要录入的内容。
3. **指标字典**：每只标的关键指标表格（指标名 / 数据源 / 频率 / 最新值 / 历史值），支持手工录入与追加。
4. **复盘视图**：对每只标的回答三问（持仓理由是否成立 / 逻辑是否被强化 / 处于逻辑兑现还是业绩兑现），保存历史回答。
5. **总览页**：全部标的列表 + 状态灯 + 最近事件 + 证伪警示。

## 数据与部署约束
- 数据存储必须用纯文本（Markdown / JSON / YAML），可手工编辑，可 git 版本管理。
- 必须沿用用户现有面板的技术栈与部署方式（静态站点）；先查明，再沿用。
- 每日维护流程必须 ≤5 分钟：新增标的 / 追加事件 / 更新指标三类操作都要快。
- 不得引入后端服务、数据库、付费依赖。
- 不得做自动数据抓取（除非用户明确要求）。
- 先做数据模型与录入流程，再做界面美化。

## 验收标准
- 用松发做样例：完整填一张卡（五问 + 证伪 + 指标 + 事件）耗时 ≤10 分钟。
- 每日追加一条事件耗时 ≤1 分钟。
- 页面可本地预览、可随现有站点发布。

## 交付物
1. 改进方案文档（数据模型 + 页面线框说明）。
2. 实现后的面板（本地预览 + 部署说明）。
3. 一页“每日 5 分钟维护手册”。
