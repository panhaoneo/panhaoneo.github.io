# 第二大脑使用指南（输入与查看）

> 建立 2026-10-10。目标：随时输入信息、随时查看当日安排。

## 一、随时输入（3 个渠道，按场合选）
| 场合 | 渠道 | 做法 |
|------|------|------|
| 电脑，AI 会话中 | 直接对话 | 把内容直接发给我，我存入 `00_inbox/` 并处理 |
| 电脑，随手记 | 放文件 | 存成 `00_inbox/YYYY-MM-DD-标题.md`，下次运行时自动处理 |
| 手机，随时随地 | 私有仓库（推荐，见第三章） | 手机 GitHub App 打开私有仓库 → 在 `00_inbox/` 新建文件 → 提交 |

## 二、随时查看当日安排（2 个渠道）
| 场合 | 渠道 | 做法 |
|------|------|------|
| 电脑 | 本地文件 | 打开 `content/assistant/09_output/今日安排-<日期>.md` |
| 手机 | 私有仓库（推荐） | 手机 GitHub App 打开私有仓库 → 看 `09_output/` 最新文件 |

## 三、手机方案：把 assistant 变成独立私有仓库（待搭建）
原理：`content/assistant/` 成为独立 git 仓库，remote 指向 GitHub 私有仓库。手机端能读能写，电脑端 push 同步。私人数据不进公开博客。

步骤：
1. 博客仓库 `.gitignore` 加一行（**必做**，防私人数据进公开站点）：
   ```
   content/assistant/
   ```
2. （可选，双保险）`hugo.toml` 顶部加一行，防构建渲染：
   ```toml
   ignoreFiles = ['^content/assistant/']
   ```
3. 把 assistant 目录初始化成独立仓库，推送到新的私有仓库：
   ```bash
   cd content/assistant
   git init
   git add -A
   git commit -m "init second brain"
   gh repo create panhaoneo/second-brain --private --source=. --push
   ```
   没有 gh CLI 时：先在 GitHub 网页新建私有仓库 `second-brain`，再把上面最后一行换成：
   ```bash
   git remote add origin git@github.com:panhaoneo/second-brain.git
   git push -u origin main
   ```
4. 手机安装 GitHub App 并登录，即可查看和新建文件。

日常同步（电脑上，一句话或两条命令）：
```bash
cd content/assistant && git add -A && git commit -m "update" && git push
```

## 四、新会话怎么唤醒助理
在任意新 AI 会话中，发一句话：
> 读取 content/assistant/08_agent/rules.md，然后按流程运行。

## 五、安全红线
- `content/assistant/` 不得提交到公开博客仓库（第三章第 1 步）。
- 医疗、法律、财务只做信息整理，不替代专业意见。
- 助理只读写 `content/assistant/`；博客其他目录为只读输入源。

## 六、你的输入会如何处理（固定流程，以孙宇晨访谈为例）
每次输入走同一条流程，原始信息和处理记录都留档。

1. **存档**：原始内容 + 分类表存入 `00_inbox/`。例：`00_inbox/2026-10-10-用户回复.md`。
2. **分类**：判为任务、项目、目标、日程、想法、情绪、决策、参考资料、待确认之一。
3. **归档**：按类别送去处；参考资料保留来源链接并提炼要点。
4. **关联**：标注与现有项目、目标的联系。例：访谈中的“数据进 MD → AI 生成日报”与本系统做法对照，标出已实现项与可选升级项。
5. **同步状态**：更新 `08_agent/state.md`、当日 `05_daily/`，必要时更新 `01_profile/`。
6. **固化规则**：可复用的约定写入 `08_agent/rules.md`。例：第 6 节“新知识输入约定”。

类别与去处对照：

| 类别 | 去处 |
|------|------|
| 任务 | `04_tasks/tasks.md`（写明为什么做、完成标准） |
| 项目进展 | `03_projects/` 对应文件 |
| 目标 | `02_goals/` |
| 日程 | `05_daily/` 与 `09_output/` 安排 |
| 想法、情绪 | 当日 `05_daily/`；值得长久保留的转 `07_knowledge/` |
| 决策 | 相关项目文件（记结论与理由） |
| 参考资料 | `07_knowledge/参考资料/` |
| 不确定 | 标记 `#待确认`，下次运行时追问 |

三条原则：
- 先存档，再处理：原始信息不丢。
- 不臆造：信息不足给默认安排，并标注假设。
- **主动思考，给建议**（2026-10-10 修订）：不纯归档——结合对你的记忆（画像、目标、项目、状态）分析每条输入，给出建议与取舍意见，目标是让你更专注核心事项。系统改造的建议直接提，动手前确认。
